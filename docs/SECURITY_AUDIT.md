# VYOMABOARD — COMPREHENSIVE SECURITY AUDIT & VULNERABILITY REGISTER

## 1. Executive Summary
An exhaustive security inspection of the VyomaBoard codebase revealed multiple critical and high-severity security vulnerabilities spanning remote code execution (RCE), unauthenticated authorization bypasses, hardcoded development backdoors, token validation bypasses, cross-tenant data leakage, and unencrypted public data exposure. 

---

## 2. Vulnerability Register

| ID | Vulnerability | Severity / CVSS | File & Location | Attack Vector & Description | Impact | Remediation Strategy |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **SEC-01** | **Host Terminal Remote Code Execution (RCE)** | **CRITICAL (9.8)** | `backend/server.js:789-819` | The WebSocket endpoint `/api/terminal` spawns a raw host process (`cmd.exe` on Windows, `bash` on Linux) via `node-pty`. Any authenticated or bypassed user can execute arbitrary shell commands on the server host. | Complete server compromise, privilege escalation, file system deletion, access to server environment secrets. | Deprecate raw host PTY spawning. Migrate terminal to isolated disposable container sandboxes or disable terminal in production unless containerized. |
| **SEC-02** | **Child Process Code Execution Sandbox Escape** | **CRITICAL (9.8)** | `backend/server.js:476-660` | The `/api/run-code` endpoint executes C, Python, JavaScript, and Java using `child_process.spawn` on the host. It attempts to block shell execution with a naive regex (`/system\s*\(/`, `/popen\s*\(/`, `/exec\s*\(/`), which is easily bypassed (e.g. `__import__('os').system('...')` in Python or `Class.forName(...)` in Java). | Host takeover, file system tampering, network scanning from backend host. | Remove host child-process execution. Route client-side execution to Wandbox or an isolated Docker sandbox with non-root user, CPU/memory limits, and network egress blocks. |
| **SEC-03** | **Hardcoded Dev Token Backdoor** | **CRITICAL (9.8)** | `backend/server.js:954-957`, `src/components/GroupChat.jsx:27` | The WebSocket upgrade handler checks: `if (token === 'dev-mode-token-12345') { request.user = { id: 9999, name: 'Dev User', ... }; return cb(); }`. Anyone can pass this string in the URL to gain unauthenticated access to Yjs, Comms, and Terminal WebSockets. | Complete authentication bypass for all real-time communication and terminal services. | Eliminate all hardcoded development tokens. Enforce Supabase JWT signature verification on all WebSocket upgrade requests. |
| **SEC-04** | **JWT Expiration Check Disabled (`ignoreExpiration: true`)** | **HIGH (8.8)** | `backend/server.js:103`, `backend/server.js:959` | All token verification calls explicitly set `{ ignoreExpiration: true }`. Expired tokens, stolen tokens, or tokens generated years ago remain valid forever. | Stolen tokens cannot be invalidated; session revocation is impossible; replay attacks are trivial. | Remove `ignoreExpiration: true`. Enforce strict expiration, signature verification, and standard token lifecycle handling. |
| **SEC-05** | **Default Insecure JWT Secret** | **HIGH (8.5)** | `backend/server.js:32-35` | `const JWT_SECRET = process.env.JWT_SECRET || 'super-secret-key-change-in-production';`. If the environment variable is not supplied, the server uses a known public string. | Attackers can forge valid JWT tokens for any user or administrator ID without credentials. | Refuse to start the server in production if `JWT_SECRET` / Supabase JWT Secret is missing or matches known defaults. |
| **SEC-06** | **Public Demonstration Server Collaborative Leak** | **HIGH (8.2)** | `src/useYjsStore.js:47` | The frontend connects to `wss://demos.yjs.dev/ws` with channel `vyoma2board-${roomId}`. This is an unauthenticated, publicly monitored demonstration server operated by a third party. | Classroom whiteboard data, exam problems, and student work are broadcast in plaintext across a public relay. | Switch Yjs provider to the authenticated internal backend `/yjs` endpoint or Cloudflare Durable Object room coordinator. |
| **SEC-07** | **Arbitrary Participant Kick via WebSocket** | **HIGH (7.5)** | `backend/server.js:915-923` | The `/comms` WebSocket processes `{ type: 'kick-user', targetId: '...' }` without verifying whether the sender is the room host, a teacher, or even a participant in the same room. | Any student or malicious actor can kick the teacher or disconnect all students from an ongoing class. | Restrict kick actions: verify sender identity against room ownership and teacher permissions stored in Supabase before kicking. |
| **SEC-08** | **Unauthenticated File Downloads from Local Disk** | **MEDIUM (6.5)** | `backend/server.js:350` | `app.use('/uploads', express.static(uploadDir));`. Uploaded school files, student assignments, and converted PDFs are served publicly without token checks. | Anyone guessing or harvesting file URLs can download private school documents, exam files, and student submissions. | Store files in private Cloudflare R2 buckets and issue short-lived (15 min) presigned download URLs only to authorized users. |
| **SEC-09** | **Exposed Public TURN Credentials in Client Code** | **MEDIUM (5.8)** | `src/context/CallContext.jsx:51-64` | Client code includes hardcoded OpenRelay credentials (`username: "openrelayproject", credential: "openrelayproject"`). | Vulnerable to credential revocation, third-party traffic sniffing, and unexpected service shutdown during live classes. | Use server-generated, short-lived ephemeral TURN credentials (e.g. Cloudflare Calls or LiveKit tokenized TURN). |
| **SEC-10** | **Client-Side Authorization for Examinations & Grading** | **HIGH (8.1)** | `src/pages/Exams.jsx`, `src/pages/ExamEditor.jsx`, `src/pages/Gradebook.jsx` | Authorization checks (such as whether a user is a teacher or has access to an exam) are performed strictly in React state (`isTeacher = isTeacherRole(role)`). Firestore collections lack RLS. | Students can bypass UI checks to view answer keys, edit grades, or submit exams after closing deadlines. | Enforce all exam access rules, deadlines, and grade modifications via Supabase PostgreSQL Row Level Security (RLS) and backend API policies. |
| **SEC-11** | **Blocking Denial of Service in Document Conversion** | **MEDIUM (6.0)** | `backend/server.js:368-402` | `/api/convert-ppt-to-pdf` executes `soffice.exe` synchronously with a 60-second timeout on the main server thread. | Repeated requests with complex PPT files will saturate server CPU and memory, freezing the main API. | Move document conversion to asynchronous background workers (Cloudflare Queues / worker threads). |
| **SEC-12** | **Broken Database Backup Crash** | **MEDIUM (5.5)** | `backend/server.js:996-1005` | The automated midnight backup cron references `dbPath`, which is undefined in `server.js`, crashing or failing silently. | Complete absence of database backup retention; data loss risk on disk corruption or server termination. | Implement automated PostgreSQL logical backups and snapshot replication to Cloudflare R2. |

## 3. Remediation Roadmap
1. **Immediate Phase 1**: Eliminate `dev-mode-token-12345`, remove `{ ignoreExpiration: true }`, deprecate `/api/terminal` host spawning, isolate `/api/run-code`.
2. **Phase 2**: Transition authentication from Firebase / custom JWT to Supabase Auth.
3. **Phase 3**: Implement multi-tenant PostgreSQL schema with Row Level Security.
4. **Phase 4**: Replace local `/uploads` with private Cloudflare R2 object storage with presigned URLs.
5. **Phase 5**: Point Yjs collaboration away from `demos.yjs.dev` to the authenticated backend `/yjs` server.
